# 将掐丝珐琅原视频压到可上传大小

## 当前状态

聊天已收到《掐丝珐琅.mp4》的附件引用，但当前附件下载工具无法把超过 **32 MiB** 的文件送进工作区。尚未取得原视频字节，所以这份原片**还没有完成压缩、画质检查或接入展馆**。原来的36秒静音图文导览仍在。

仓库提供 `Windows_压缩视频.bat` 和 `scripts/compress-video.mjs`，让你直接在保存原片的电脑上操作；输出限制为 **30 MiB（31,457,280字节）**，给附件传输留出余量。处理成功后，将生成的视频重新上传到聊天，再继续替换第一片及保存素材。

## Windows 操作

1. 下载包含本轮更改的完整项目并解压。确保已安装项目需要的 Node.js 24.15或更高的24.x版本。
2. 电脑还需 FFmpeg（包括 `ffmpeg` 和 `ffprobe`）。若未安装，在 PowerShell 运行以下命令，安装结束后关闭并重新打开终端/启动文件：

   ```powershell
   winget install --id Gyan.FFmpeg --exact
   ```

   这一步由你在电脑上执行；项目脚本不会自动安装软件。若电脑没有 winget，可从 <https://ffmpeg.org/download.html> 的 Windows builds 下载并把 `bin` 目录加入 PATH。可运行 `ffmpeg -version`、`ffprobe -version` 检查是否可用。
3. 将你电脑上的原视频拖到 **Windows_压缩视频.bat** 图标上。也可双击 bat，在窗口输入视频完整路径后回车。
4. 等待窗口显示“压缩完成并已校验”。结果在项目的 **work/video-export/** 中，文件名带“30MiB以内”和时间。窗口会显示实际大小；原视频不覆盖。
5. 先播放结果，检查字幕/细线条、人物、声音和是否完整，再把这个输出 MP4 上传到聊天。

高级用法（Windows、macOS、Linux均可，先安装FFmpeg）：

```sh
node scripts/compress-video.mjs "原视频的完整路径.mp4"
```

## 画质与大小如何取舍

源文件已在30 MiB以内且为兼容的H.264/AAC MP4时，直接复制并校验，不重复编码，保留原画质。其他文件根据实际时长预算码率，使用 H.264 + AAC 两遍编码：第一遍分析画面，第二遍按体积预算生成 MP4。保持画面比例与原有音轨，不裁剪内容；不放大原画面。分辨率根据可用码率选择，最高为1920×1080（竖屏对应1080×1920），较长视频会降到720p、540p等；高于30帧的源会转换为30帧。为播放兼容，视频使用常见的 yuv420p 像素格式。

输出会检查大小、编码、音轨数量和时长。超过30 MiB会降低码率重试，最多三轮；无法在限制内得到可用结果会明确报错。源视频越长，固定大小下可分配给每秒画面的数据越少，无法承诺所有素材都与原片肉眼一致。工具保留全部音轨，不额外复制独立字幕轨；原画面中已经烧录的字幕属于画面，会保留。

不要为了聊天上传而覆盖保存的原片。压缩副本可先用于接入、预览；将来若能提供原片下载链接，可再按实际需要更新更高质量版本。

## 保存与展馆替换

`work/` 已被 Git 忽略，原片、压缩过程和输出不会自动提交 GitHub，也不会自动改变展馆。收到可读取副本后，还需核对画面、音轨、时长与授权，保留旧导览并选择新素材路径，更新默认视频说明、封面和必要分片，然后构建、测试、提交工作分支。

如果仅在自己的安装里先试播，也可登录 `/admin` 的“影片与360°”上传到第一槽位；该操作会立即更改当前数据目录的视频，且不等于将视频保存到 GitHub。先确认使用的是 `data/local-preview/` 测试目录。
