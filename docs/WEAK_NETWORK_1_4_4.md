# 1.4.4 校园弱网修复与完整交付记录

日期：2026-11-03。基于已有1.4.3及功能修复提交7617dac继续；没有从零重写，也未修改学校网络或发布原Sites。用户已授权将需要的优化同步到GitHub工作分支。原main的域名记录不改动。

## 已证实的程序问题

旧构建在浏览器只打开首页、不操作时，会请求全部91张凤冠WebP。原图为1600×1600，共33,640,600字节。十台冷缓存同时加载，仅这组图片约320.82MiB；每页4个预取任务也会与视频争用连接。旧版没有图片级恢复入口，网络失败容易需要整页刷新或重启后再试。

这不是对现场唯一根因的认定。学校不同楼层的AP隔离、VLAN权限、Mac休眠、实际IP变化、无线带宽和电脑后来上传影片的码率仍需现场核对。重启恢复不能证明某一种原因。本轮没有取得学校访问日志、没有亲自连接学校网络。

## 实现

- `web/use-frame-loader.ts`：当前帧优先，然后只预取相邻一帧；索引变化或全屏切换时取消过期请求。URL缓存有上限，不保留整组Image对象。当前帧有两次有限尝试，失败后用户可单独重试；等待新帧时保留已成功的画面。自动旋转按相邻帧到达情况推进，避免慢网空白。
- `ZoomStage`继续支持旋转、平移、双指和滚轮缩放、键盘、滑条、自动旋转及全屏；100%点击平移仍会先放大。`ImageGallery`保留16:10文物列和课程图文顺序，增加缩略图失败提示及点击重试。
- 公开影像展厅使用preload=none，播放前不抢先读视频。播放缓冲或失败显示恢复入口；重载会尽量恢复播放位置，不再把所有源不可用错误都断定为编码损坏。后台发布前的画面/编码检查不移除。
- 静态媒体增加ETag/Last-Modified与304复用，Range/If-Range和206继续工作；HTML保持no-store且不使用同尺寸/时间的验证器，避免新包页面被旧HTML缓存遮蔽。文件权限/读取异常仍记录。
- `/connect`增加实际服务、资料、图片及视频分段自检，外部同源脚本遵守原CSP，不提交测试问卷。连接页可复用缓存HTML，减少重复二维码计算。
- 多网卡时可选择地址；IP消失会提醒换二维码。Mac进程运行时尝试防闲置休眠，仍需接电开盖。两系统增加一键备份；备份源库只读打开，缺配置/数据库时不凭空创建空数据库。

## 素材与完整包

91帧原图及三部影片不重新编码或压缩。此前已取得的第一片为29,657,745字节、113.150998秒、960×540、60fps、H.264+AAC；原文件保留，8秒封面随包提供。其MP4索引位于文件开头；现有第二/三默认片也已符合渐进读取。旧36秒导览仍保留。

第一片选择优先顺序继续保护已上传视频和隐藏设置；若有原手动导入文件film-01-qiasi.mp4，继续优先；否则新包可使用已提供113秒版本。只有用户电脑上存在的后续文件无法从聊天自动取得，必须按指南保留旧活动data。

`scripts/package-desktop.py`输出Windows和Mac独立完整ZIP，内置各自x64/ARM64官方Node24.22、许可证和SHA-256来源。运行无需安装开发依赖。为兼容单文件限制，每系统另有第1包ZIP与第2段，工具校验合并后解压，旧项目和下载段都保留。下载标签只包含下载文件，源码在工作分支及其PR。

完整使用和旧data迁移见 [DESKTOP_1_4_4.html](DESKTOP_1_4_4.html)。不能把只拷贝SQLite或Excel当成完整迁移；原上传素材在data/media内，手工放在旧dist里的影片另行保留。
