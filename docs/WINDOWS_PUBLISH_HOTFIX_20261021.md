# Windows 1.4.3视频发布与扫码入口修复

适用于已经生成的1.4.3完整部署包。只更新程序，不含视频、图片、Node或data，也不会改写原密码、留言和已上传视频。无需重新下载整站或重新合并完整包。

1. 在原展馆黑色窗口按Ctrl+C；若提示终止批处理，输入Y并回车。
2. 全部解压本修复ZIP，双击“安装Windows视频与入口修复.bat”。不需要管理员身份，不需要拖入文件夹。
3. 弹窗中选择原完整部署包内含package.json、runtime、dist的项目文件夹，点确定。修复器优先使用完整包内置的Node。
4. 看到修复已安装后，重新双击原项目的Windows_同WiFi扫码启动.bat。
5. 自动打开的是网页形式的二维码入口，包含主网页和管理员后台链接。若没有弹出浏览器，可双击新增加的Windows_打开入口.bat，或复制终端里“二维码与入口”的网址。
6. 已有网页按Ctrl+F5刷新一次，确保读取新版程序。之后后台发布会核对公开影片地址，返回公开页或进入影像展厅会重新读取最新影片。

终端将显示当前实际使用的影片来源。已经通过后台上传时，不再错误提示需要手动放置film-01-qiasi.mp4。不需要往assert或assets文件夹重复放视频。

视频仍按400MiB上限及H.264/AAC兼容要求上传。看到“视频已保存并发布”后，可点击后台的“查看当前影片”直接播放实际文件，再到公开影像展厅确认。旧封面不会自动改变；当前后台已有“影片封面、字幕与显示”里的“更换封面”，选图后需点击保存影片资料并发布。

Mac或Windows后台已成功发布的视频副本位于本项目data/media/videos；源视频不必保留在桌面，但建议另行备份。请完整保留项目data和隐藏的.runtime文件夹。

修复前的程序文件备份在backups/windows-publish-hotfix-20261021。程序文件若与原1.4.3存在其他修改，修复器会停止并保留它们。

已进行云端接口与浏览器验证；Windows默认浏览器启动属于平台操作，未进行Windows真机测试。若仍显示旧视频，请核对终端“当前数据目录”和后台所在网址，保留完整错误信息。
