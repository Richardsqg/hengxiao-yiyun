横小艺韵1.4.4：先打开这一页

这是在已有项目上整理的完整Windows/Mac部署包，已整合此前平移、手机导航、留言和视频发布修复，无需再装旧补丁。学校logo、默认“凤冠360展示”、课程、图片、三部影片、91帧凤冠、登录后台、问卷及Excel继续保留。

这是电脑本机/校园局域网程序。电脑需开机，手机所在网络需允许访问这台电脑。此包不是公网正式网站，也不能绕过学校不同楼层的网络隔离。

一、完整下载、合并

  1. 选择对应系统的两个下载文件：第1包.zip＋第2段.zip.part2。两个都下载完整，不要混用Windows和Mac文件。
  2. 全部解压第1包到一个新的本机文件夹。第2段保持原样，不用打开或解压。
  3. Windows双击“Windows_生成并解压完整包.bat”；Mac双击“Mac_生成并解压完整包.command”。在弹窗里选择本系统的第2段。
  4. 工具将校验SHA-256、合并并解压。得到 完整部署包/hengxiao-yiyun-1.4.4-desktop。后续启动要进入这个项目文件夹；不要在下载段或ZIP内部运行。

如已存在同名的未完成目录，合并器会停止，避免覆盖。保留它，换一个新文件夹重新解压第1包即可。Windows建议选择较短的本地路径。不要直接在网盘同步目录或跨网共享目录运行。

二、先决定是否保留旧内容

首次试用可直接下一节。如果旧电脑已有密码、留言或后来上传的视频，先按下面做：

  1. 先停止旧服务：在原黑色窗口按Ctrl+C；Windows询问终止批处理时输入Y。
  2. 保留原项目整份不动，并把原活动数据目录另存一份。原启动窗口的“当前数据目录”可以帮助确认。
  3. 在新程序第一次启动之前，将旧活动数据目录完整复制为新项目的 data 文件夹。必须含config.json、gallery.sqlite及media等原有内容，不只复制数据库文件。
  4. 1.4.3通常就是旧项目的data。若旧版本实际用的是data/portable或data/local-preview，应将该活动目录的内容复制到新项目data，不能把空的父目录当成原数据。
  5. 如果新项目已试运行产生data，先停止新服务并将新data改名保留，再复制旧data，不直接合并或覆盖。

若你以前用“导入第一部视频”工具手工放置了 旧项目/dist/assets/film-01-qiasi.mp4，且想继续使用这份影片，也将它复制到新项目同一路径。后台上传的影片则随整个data/media一起保留。

本包默认第一片包含此前提供的约113秒、60fps掐丝珐琅视频。后来只上传到你电脑后台的影片和留言，我无法从聊天取得，需通过旧data保留。 不要把data或备份上传GitHub。不要在两台电脑上同时通过网盘共享一个SQLite目录。

三、Windows打开

  1. 进入完整项目，双击 Windows_同WiFi扫码启动.bat。只在电脑看时用 Windows_启动.bat。
  2. 首次由你设置管理员密码，至少12个字符，输入时不显示。已有旧data配置则继续使用原密码。
  3. 多网卡时按提示选择手机所在校园网能访问的地址；使用网线时确认选的是对应地址。
  4. 等到显示服务已启动，浏览器将打开二维码与入口页。保持窗口开启；允许Node在需要的校园网络配置中接收连接，不需要关闭整个防火墙。

四、Mac打开（Intel及Apple芯片）

  1. 需要 macOS13.5或更新。双击 macOS_同WiFi扫码启动.command；只在电脑看时用 macOS_启动.command。
  2. 按提示设置密码或沿用旧data；多个地址时选择正确校园网地址。
  3. 若.command无执行权限，打开“终端”，输入 bash 和一个空格，把启动文件拖入终端，再按回车。
  4. 如果系统提示下载安全确认，先核对来自自己的项目，按针对该文件的系统提示处理。不要关闭系统整体安全保护。
  5. 服务运行时会尝试防止Mac闲置休眠；仍请接电、开盖，不要手动睡眠。合盖、关机或网络断开仍会停止访问。

完整包已经附带官方Node24.22.0及许可证，自动选择相应CPU。正常运行无需安装Node、npm、数据库服务器、Homebrew、Xcode或浏览器插件。另存视频的转码工具才需选装FFmpeg，不是普通查看的必需品。

五、手机、后台与备份

扫码进入启动窗口显示的实际网址。首页仍为“凤冠360展示”，公众端保持四入口。后台由入口页的“管理员后台”打开，或在同一个展馆网址后加 /admin。登录后修改图文、上传图片/视频/实拍360组，查看留言和导出Excel。

暂停上传后，Windows运行 Windows_备份数据.bat；Mac运行 macOS_备份数据.command。备份在本项目 backups，请复制到另一台设备保存。Excel只用于阅读统计，不能替代完整备份。

电脑和手机退出旧页面后重新打开/扫码，确保加载新版。电脑可强制刷新：Windows为Ctrl+F5，Mac为Command+Shift+R。电脑换网络、IP变化后重新启动并更换二维码。系统检测到原IP消失时会在终端提醒。

六、本版实际修了什么

  • 凤冠由进首页即预取91帧，改为当前帧优先、相邻一帧按需预取。保留1600×1600原图，不降低原图质量。当前帧未到时保留上一张画面，不闪成空白；错误可单独重试。
  • 文化寻根图片载入失败会显示“点击重试”。影片打开前不抢先读取视频，播放缓冲和失败均有提示，可以重新载入并检查连接。
  • 静态媒体增加ETag及修改时间校验，支持304复用；视频保留Range/206。HTML仍不缓存，避免一直停在旧页面。
  • 继承100%可点平移、放大仍能旋转、手机四导航避让及私网HTTP问卷提交修复。完整91帧仍在包内，自动旋转时按网络可用速度逐步加载。

七、不同楼层仍打不开时，先检查这一页

在出问题的手机上打开启动窗口的 http://实际IP:端口/connect，点击开始连接自检。它会检查服务、展馆资料、图片读取及视频分段，不会提交测试问卷。

结果下一步
页面/健康检查都打不开确认电脑和窗口仍在运行、IP正确；请学校网管检查该楼层网段、访客/AP隔离和电脑入站权限。同WiFi名称不保证互通。
资料正常，图片/视频404检查完整包及旧data/media是否复制完整，保留报错，不删除数据库。
视频不是206或返回HTML可能有网络网关/代理改写，交给网管核对请求路径与分段响应。
全部正常但多人播放慢电脑优先接网线，检查AP负载、视频实际码率和无线覆盖。十路约2Mbps视频需要约20Mbps有效吞吐，不能只看“已连接WiFi”。

请保留重启之前的自检结果、终端报错和时间。先1台、再5台、再10台从不同楼层实际扫码；每台检查图片、三部影片，并提交一份问卷后核对后台。

八、验证边界与缺少资料

本轮已在Linux中验证构建、70项Node测试、Chromium桌面/触屏交互，以及10个独立冷缓存客户端在模拟2Mbps/120ms条件下加载和提交。10份问卷真实落库并能在后台查看、导出；故意断开图片/视频后的重试通过。

首屏凤冠序列由91帧约32MiB降为2帧约0.80MiB，指的是这组序列的初始加载，不等于所有视频总流量减少，也不是对校园WiFi速度的保证。原图和三部影片未重新压缩。
