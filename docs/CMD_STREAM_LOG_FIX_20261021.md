# Windows 1.4.3：CMD中的ERR_STREAM_PREMATURE_CLOSE

截图中网页正常、服务仍在运行；黑色窗口中的 `Request failed: ERR_STREAM_PREMATURE_CLOSE` 表示某次传输尚未完成就关闭了连接。浏览器切换影片、拖动播放进度、刷新或离开页面时，会取消旧视频请求。在原1.4.3中，这些正常取消也会被统一当成失败写入终端。仅凭这条日志不能判断视频损坏或服务崩溃；网络断开也可能中断传输。

本次在当前main的1.4.3（09168b8）上复现：默认视频和后台上传视频的Range请求，在收到部分字节后取消都会打印同一条报错。程序修复只改变 `runtime/server.mjs` 的响应传输处理：正常客户端中断不误报，底层文件读取故障、服务端源流异常仍保留错误记录。没有将所有相同错误码一律屏蔽，没有更改页面、视频、360图片、数据库或管理员密码。

## 初学者安装步骤

小修复下载（只含安装工具与一个程序文件，不是完整软件）：

<https://github.com/Richardsqg/hengxiao-yiyun/archive/refs/tags/patch-1.4.3-cmd-log-20261021.zip>

仓库私有，先在浏览器登录拥有权限的GitHub账号再下载，未登录可能显示404。

1. 如果展馆当前正常可用，可以继续使用；这是改善日志处理的小修复，不需要重装Node、插件或系统，也不需要改防火墙。
2. 准备更新时，在原展馆黑色窗口按 **Ctrl+C**；如询问终止批处理，输入 **Y** 并回车。
3. 完整解压小修复ZIP，双击 **安装CMD日志修复.bat**。
4. 在弹窗中选择截图中的原 `hengxiao-yiyun-1.4.3-desktop` 文件夹，里面应有 `package.json`、`runtime`、`dist`。不要选择 `data` 子文件夹。工具复用原完整包内的Node，不需要管理员身份。
5. 安装器先核对原程序与修复文件，自动把旧程序保存在 `backups/stream-log-fix-20261021/runtime/server.mjs`，然后只替换 `runtime/server.mjs`。`data`、密码、留言、上传视频和图片均不改写。
6. 用原启动文件重新启动，检查视频播放、切换与拖动进度。保持服务窗口开启。

若提示“程序文件与原1.4.3不同，已保留未覆盖”，说明本机文件另有改动或不属于截图对应版本；不要强制覆盖。保留完整提示后再核对实际程序。此修复不用于把旧1.4.2升级为1.4.3。端口检查默认3000；若自行改过端口，仍须先手动停止旧服务。

维护者可运行 `python3 scripts/package-stream-log-fix.py` 重新生成小修复。下载标签仅保存生成的安装文件；实际源码与测试在修复工作分支及其PR，不能把这个小修复标签当作完整项目检出。

新回归检查分别覆盖默认视频取消、后台上传视频Range取消与后续继续请求、真实磁盘读取错误，以及服务端源流自行提前关闭。后两种异常仍会记录，包括与浏览器取消相同的 `ERR_STREAM_PREMATURE_CLOSE`，以免隐藏真实问题。

本轮 `npm run build` 成功，`npm test` 实际62项通过、0失败（包含新增4项传输回归）。小修复安装器在隔离目录验证了复杂路径、原程序备份、只更新一个文件、data不变、重复运行安全、已有修改与错误项目拒绝覆盖。Windows弹窗本身未在Linux模拟为通过。

当前是在Linux运行Node进行检查，没有替用户操作Windows。Windows弹窗、双击安装与实际校园网络仍需在本机验证。若出现视频卡住、上传失败、数据无法保存或进程退出，即使错误码相同也应进一步检查，不能统一视为无影响。
